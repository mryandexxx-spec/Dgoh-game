# Dune GoH — правила архитектуры и разработки

Обязательны для всех доработок после рефакторинга (фазы 0–7). При расхождении с инструкциями проекта главный этот файл.
Целевая платформа — iPhone (PWA, Safari/WebKit), desktop вторичен. Команды и устройство тестов — `README.md`; состояние и открытые вопросы — раздел «Открыто» в `CHANGES_STATUS.md` (§8).

## 1. Модули и слои

| Папка | Что внутри | Может импортировать |
|---|---|---|
| `data/` | таблицы: персонажи, кампании, награды, SVG-контуры как данные | `data/` |
| `logic/` | чистая игровая логика (бой, экономика, прогресс), тестируется в Node | `data/`, `logic/`, `core/` (кроме DOM) |
| `core/` | старт, сохранение, состояние, rng, форматирование, `dom.js` | не `ui/` (кроме `core/boot.js`) |
| `ui/` | экраны, HTML, обработчики, оверлеи | всё, кроме обратных зависимостей в logic/data |
| `render2d/` | 2D-фоллбек сцен и FX для ui | `data/`, `core/` |
| `render3d/` | Babylon: EngineHost, сцены, персонажи, окружение, `quality.js` | `data/`, `core/` |
| `assets/` (src) | загрузчики ассетов, карта путей | — |

- В `logic/` и `data/` нет DOM, HTML, Babylon, импортов `ui/` и `render*/`. HTML-разметка — только в `ui/`.
- Новая механика = данные в `data/` + чистая логика в `logic/` + отображение в `ui/`. Связь logic → ui — только хуки/подписки (`rewardHooks`, `onPersist`), не импорт.
- Один модуль — одна ответственность; модуль больше ~600 строк делить.
- `src/` правится вручную. `modularize.mjs`, `extract-pass1.mjs`, `split-css.mjs` не запускать. Перенос объявлений — `node tools/move-decl.mjs`.
- Порядок исполнения — цепочка: импорт предшественника стоит первым; если из него уходит последний именованный импорт — `import './пред.js'; // порядок исполнения`. Новый модуль встраивается в цепочку и в `tools/split.config.mjs`.
- Проверка: `node tools/check-deps.mjs` (новых нарушений 0), `node tools/check-bundle.mjs dist/pwa/app.js`.

## 2. 3D (render3d)
- Один Engine — `EngineHost` (`engine-host.js`): стек владельцев `mount/release/forget`, один render loop. Свой Engine, свой rAF/`setInterval` для 3D — запрещены.
- Сцена реализует `GameScene` (`game-scene.js`): create → `wake(host, o)` → `update(now)` → `sleep(o)` → `dispose()`. Режим кадра — `mode(now)`: active 60 / idle 30 / idleLow 20 / static (кадр держится) / paused. Без активности сцена обязана уходить в idle/static.
- Всё созданное освобождается в `dispose`; ресурсы общего пользования — через кэш ассетов, эффекты — через пул FX.
- Компиляции: `Effect.PersistentMode`; новые материалы прогревать (`forceCompilation`) — после wake 0 компиляций.
- Потеря контекста: сцена реализует `contextLost()`; следующее `engineHost()` создаёт новый движок.
- В кадре не читать размеры DOM (`clientWidth`, `getBoundingClientRect`) — кэшировать по resize.
- Babylon — ленивый чанк `babylon3d.js` (только модульные импорты `@babylonjs/core`, новые классы — проверить попадание в чанк). Без WebGL игра работает на 2D-фоллбеке.

## 3. Профили графики
- Все параметры качества — только в таблице `render3d/quality.js`: профили `high` / `med` / `low` и ступень `low30` (LOW + 30 fps в бою, только автопонижение). Значение — скаляр или пара `[desktop, phone]` (phone — меньшая сторона < 600 px). Доступ: `gfx(small)`, `gfxLevel()`, `gfxStep()`.
- Не хардкодить в сценах: dpr, MSAA, тени (размер, частота, PCF), glow, bloom, DoF, SSAO, grain/chromatic/sharpen, пробники отражений, сетку земли, число частиц, частоты кадров.
- Новый эффект/объект задаёт поведение для каждого профиля:
  - HIGH — полный вид (desktop по умолчанию);
  - MED — по умолчанию на телефоне: дешёвый вариант (запечённое вместо реального времени, без пост-эффектов);
  - LOW — выключено или минимум; смысл сцены не теряется.
- Хранение — `localStorage` `dune-gfx` = `{p, auto, bad, good, noUp}`; в сохранение не класть. Автопонижение (`gfxReport` по итогу боя) и переключатель «Графика: Авто/Высокая/Средняя/Низкая» не обходить.
- Проверки: `tests/smoke/ab.mjs --gfx` (минимум MED `--phone` и LOW; HIGH — если затронут его вид), `tests/smoke/perf.mjs --gfx` для затронутых профилей.

## 4. Производительность на iPhone
База — цена кадра последней выкатки; ухудшение без согласования не допускается. Ориентиры (perf.mjs, SwiftShader, v64; draws / проходы / Мпикс / RT МБ):

| сцена | phone dpr3, MED | phone, LOW | desktop, HIGH |
|---|---|---|---|
| бой | 551 / 16 / 4,0 / 45 | 525 / 10 / 2,1 / 24 | 1964 / 48 / 20,6 / 169 |
| лагерь | 344 / 15 / 4,0 / 29 | 317 / 10 / 2,1 / 17 | 1193 / 40 / 15,4 / 114 |
| окно героя | 120 / 19 / 1,8 / 42 | 75 / 9 / 0,4 / 22 | — |

- Рост > 10% по любому показателю MED/LOW — на согласование с вариантами снижения. Числа — SwiftShader, заменить на данные `?perf` с iPhone, когда появятся.
- Старт: app.js ≈ 0,56 МБ — всё тяжёлое лениво; tti (`3d.mjs --tti`) не хуже базы.
- DOM/CSS: 0 layout на кадр в простое; анимации только `transform`/`opacity`; бесконечные анимации паузить под оверлеями и в скрытых экранах (как `.battle.fin`); HUD боя обновлять точечно, не пересобирать `innerHTML` целиком; без безусловных периодических перерисовок. Проверка — `tests/smoke/dom.mjs` (desktop и `--phone`), forced layout 0.
- Память: за циклы `3d.mjs --cycles` — 1 контекст, без роста meshes/textures.
- Финал — на iPhone через оверлей `?perf` (или 5 касаний по номеру версии).

## 5. Ассеты и PWA
- Модели, текстуры, анимации — файлами в `dev/assets/` (имя с хешем подставляет сборка), текстуры — KTX2 (`tools/encode-ktx2.mjs`, результат коммитится). Не base64 в коде. Исходники вне сборки — `dev/assets-src/`.
- У каждого ассета фолбэк при ошибке загрузки (процедурная модель, без анимации и т. п.).
- Новый статический файл — в кэш SW (`src/pwa/sw.js`), проверка `tests/smoke/sw.mjs` (обновление, офлайн).

## 6. Сохранения
- Ключ `dune-goh-v1`. Изменение схемы — только с миграцией в `fillSave`/`loadSave`; старые сохранения (`tests/fixtures/saves/`) не ломаются, golden `saves` подтверждает.

## 7. Процесс
1. Проект/макет на согласование: какие слои и модули меняются, новые данные и миграции, влияние на бюджеты и профили. Визуальное — макет; заметные изменения рендера — A/B до/после.
2. Реализация небольшими шагами; между шагами — `check-deps`, `check-bundle`, golden `--no-dom`.
3. Перед выкаткой — golden на артефакте и PWA (`npm test`); render3d — `3d.mjs --cycles 2` desktop и `--phone`; DOM/CSS — `dom.mjs`; статика/SW — `sw.mjs`. Известные FAIL песочницы сравнивать с базой. `--update` эталонов — только после согласия владельца.
4. Механики и баланс покрываются golden (battles/meta) или новыми табличными случаями.
5. Выкатка: номер в `version.json` +1; коммит в main; публикация `dist/artifact.html` со всеми файлами из `dist/artifact-files.json` в артефакт.

## 8. Журнал доработок (`CHANGES_STATUS.md`)
- Единственное место записи функциональных доработок; `PHASE*_STATUS.md` — только фазы рефакторинга (архив).
- Перед началом доработки — прочитать «Открыто» и учесть в проекте.
- Каждая выкатка в том же коммите: запись `## vNN — что (дата)` (сделано · замеры · проверки · что проверить на iPhone) + актуализация «Открыто»: добавить новые пункты, подтверждённые владельцем перенести в «Закрыто» с версией и датой, неактуальные убрать.
- Результат проверки на iPhone от владельца — вносить ближайшим коммитом. Записи старше ~10 версий сворачивать в сводку.
