## 2. Художественная цель — Cinematic Dune
Монументальная, сдержанная научная фантастика: крупные формы, правдоподобные материалы, выразительные силуэты, кинематографический свет. Не фэнтезийное золото на каждом элементе, не кислотный киберпанк, не голограммы и свечение ради свечения. Герой — основной визуальный объект; имя и мощь важнее второстепенных подписей. Inter остаётся базой. Информационные блоки поверх цельной сцены, умеренные затемняющие подложки по контрасту, рамки только там, где они несут смысл (тир, доступность, выделение). Одна навигационная структура для всех тем, семантические цвета не перекрашивать. Ульта легенды закреплена, все действия прокачки и ДП доступны. Легенды отличаются постановкой, не перегруженным декором.

Гибридное окружение: дальний matte painting (без запечённого UI/героя), средний/передний план из компактной настоящей геометрии, реальный пол с PBR и контактной тенью. Подиум заменить площадкой локации. Свет должен совпадать с художественным планом. Параллакс/перекрытия только в пределах пользы и бюджета, не обязательный эффект. На LOW сохранить композицию и читаемость, не превращать сцену в другую стилистику.

| Фракция | Средний/передний план |
|---|---|
| Фримены / Арракис | Песок, скалы, стены ситча |
| Атрейдес / Каладан | Каменная терраса, колонны, знамёна, прохладный морской свет |
| Харконнен / Гьеди Прайм | Металлическая площадка, монолитные стены, жёсткий почти монохромный свет |
| Коррино / Кайтэйн | Дворцовый пол, массивные колонны, сдержанное золото |
| Бене Гессерит / Валлах IX | Каменные арки, приглушённый свет, тёмный текстиль |
| Мыслящие машины | Металлические конструкции, энергетические каналы, холодный свет |

Сохранить ключи UI-10 и визуальные overrides (Муад'Диб — frem, Джессика — atr, легендарный Барон — hark), не связывать тему с save или боевыми правилами.

## 3. Производственный процесс AI + 3D
1. Art Bible: общий визуальный язык, материалы, свет, типографика, масштаб деталей, примеры «да/нет».
2. AI concept art: OpenAI Image Generation для концептов, фонов и референсов; отдельные пригодные для производства ассеты, не готовый скриншот с нарисованными кнопками.
3. 3D production: Meshy для кандидатов моделей, оружия, пропсов и архитектуры; Blender для ручной доводки, постановки, UV, ретопологии, рига и baking. Генерация не гарантирует готовность для runtime.
4. PBR: Substance 3D Sampler как опциональный инструмент; Poly Haven/ambientCG как источники материалов и HDRI с проверкой лицензии. Albedo/normal/roughness/metal/AO, согласованная экспозиция и свет. Mixamo — возможный источник клипов после проверки прав и ретаргетинга.
5. Mobile: LOD при необходимости, KTX2/JPEG fallback, собственный DGM/GLB source pipeline, сокращение материалов/draw calls, ленивые загрузки, один активный набор ресурсов, provenance и лицензии. Никаких закупок/платных генераций без согласованного расхода; проверить разрешение на встраивание в публичную PWA. Не копировать чужие игровые/киношные ассеты.
6. Visual QA: реальные кадры Babylon.js и сравнение с референсом и baseline, а не только AI-превью, build или зелёный CI.

Не менять Babylon.js: текущий WebGL-стек поддерживает необходимую технику. Не добавлять второй engine/canvas/RAF, WebGPU или новый UI framework. Использовать текущие B3, EngineHost, GameScene, загрузчики и quality.js.

## 5. Приёмка и ограничения
- Экран iPhone PWA/Safari только landscape, без общего скролла; допускается внутренний скролл компонентов. Safe areas, доступные touch targets, focus, contrast, длинные русские имена и значения.
- Не терять: навигацию между героями, роли/фракции, умения, закреплённую ульту, шесть слотов/состояния экипировки, уровни, звёзды/осколки, ДП, статы, биографию, доступные/недоступные действия. Сохранения, экономика, RNG, боевой код и Web Locks вне объёма.
- Один EngineHost, один WebGL context, lifecycle/dispose и offline fallback. HIGH/MED/LOW через quality.js; MED — основная мобильная цель; LOW — без лишних FX. Не добавлять непрерывные дорогие эффекты.
- Снимать сравнимые A/B на текущей базе (v156 на дату аудита, актуальную версию уточнить перед реализацией), 844×390 и 667×375, минимум MED/LOW, одинаковый герой/состояние/качество. Проверить реальные кадры, соответствие света, отсутствие подиума-наклейки, читаемость и композицию.
- Замерить frame time/p95, draw calls, GPU/RT memory, загрузку, ресурсные циклы; рост >10% по действующим бюджетам ARCHITECTURE.md требует согласования. Софтварный WebGL — не доказательство производительности на iPhone. Физическая приёмка и нагрев остаются отдельным пунктом.
- CI: текущий diff-sensitive процесс — короткий smoke плюс затронутые UI/3D/PWA проверки, обязательная strict architecture; полный регресс только при действительной необходимости по правилам. Не обходить проверки. Код в отдельных ветках, PR, merge после зелёных обязательных проверок; визуальные эталоны не обновлять без согласования.
- GFX-01 не требует изменения runtime или версии. После макетов GFX-02 — реальная разработка, а не новый круг общих концептов.
