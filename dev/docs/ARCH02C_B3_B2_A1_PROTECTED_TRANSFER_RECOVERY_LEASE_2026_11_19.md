## Scoped A1 implementation

**Protected manual import:** In `ui/wiring.js`, a B2 import preview performed under an armed writer gate additionally requires a current Web Locks owner with exact currently verified primary bytes and passing writer.check(). The pending intent is permanently tagged `writer` or `legacy` (default legacy maintained for historical v140-style tests). Confirmation rechecks unmutated live S, no battle, and the original expected primary. Denied writer-gated UI transfer entrypoints also refuse inspection before Web Locks ownership. If tagged writer, it commits *synchronously* through `loadSave.writer.commit` and **never** falls back to `loadSave.checkpoint.commit`. The writer's checkpoint commit preserves the previous valid primary backup, rereads the current exact raw under the held lock and checks new primary write/readback. On success: invoke the existing core/boot writer lifecycle blocker through a UI-owned callback, synchronously denying all further game input, release writer irrevocably, do not graft imported save into stale S or existing timers, and show the safe reload screen. The user must reload for a new writer lease. On conflict/quota/uncertain, no activation of candidate or acknowledged success; stale/conflicted/uncertain writer sessions release authority and show the blocked screen rather than continue mutable gameplay. The original non-gated B2 behavior remains unchanged to keep historical tests and legacy mode stable; this does not make default legacy safe.

**Empty localStorage import:** A completely empty origin may bootstrap `newSave()` only under the *normal* opted-in writer gate. That initial owned/verified checkpoint is the exact expected pre-import raw; importing external verified v1 preserves the new placeholder as backup, confirms imported primary, releases the lease and reloads it on a fresh page. An origin with missing primary but an existing verified backup remains `recovery-required` and does NOT auto-create a fresh save.

**Recovery-only authority:** `loadSave.writer.acquire({purpose:'recovery'})` can be invoked only after `enableGate()`, when live `S === undefined`, with a native available exclusive Web Lock and a verified B1 backup plus a missing/corrupt/invalid primary. It NEVER grants gameplay writer authority, never boots the game, and denies unsupported future-version primary. While held, the caller explicitly inspects the backup and passes the exact observed primary raw and backup envelope into `loadSave.writer.recover({expectedPrimaryRaw,expectedBackupEnvelope})`. The latter rechecks primary under the lease, calls the existing strict B1 restore preflight, verifies exact bytes, and **releases the lease after the first attempt even on failure or uncertainty**. A fresh page/realm is mandatory for subsequent startup. Direct `checkpoint.recover` remains denied when gated; `writer.commit` refuses a recovery-only lease. No automatic recovery or user-writable reset.
