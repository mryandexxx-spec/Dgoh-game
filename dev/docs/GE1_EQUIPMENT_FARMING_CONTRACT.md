# GE1 — разделённый фарм снаряжения (утверждённая экономика, 11.11.2026)

**Статус:** баланс и миграция согласованы владельцем; HTML-макеты интерфейса ожидают отдельного визуального утверждения. Ветку GE1 не сливать в main до прохождения CI и приёмки макетов.

## Подтверждённые правила

1. Готовое снаряжение — самостоятельный тип добычи и учёта в инвентаре, не фрагмент. Любой полученный целый предмет может быть немедленно надет в подходящую свободную ячейку без крафта и дополнительной стоимости; при повторном использовании расходуется одна единица запаса.
2. Шанс готовой вещи **на бой, для конкретной вещи и конкретной миссии**: I–III 2% (2 миссии на вещь); IV–V 1% (1); VI–VII 0.5% (1); VIII–IX 0.2% (1); X 0.1% (1); XI–XIII 0% (0).
3. Для VI–XIII составные части из разных компонентов (например, Сердечник и Линза). У каждого материала отдельный ключ инвентаря и отдельные источники добычи. Не более 3 миссий для фрагментов одного компонента. Два компонента **одного предмета не делят миссии**.
4. Старые общие фрагменты предмета в `S.inv[itemId]` сохраняются в качестве **универсального старого ресурса**, расходуемого до исчерпания при сборке любых компонентов этого же предмета; не конвертируются и не уничтожаются при миграции. Уже надетое снаряжение и накопленные собранные компоненты сохраняются.
5. Различать награду типа `completeGear` и `componentFragment` в бою, симуляции и экранах источников. Вычисление доступности кнопок использует реальные таблицы наград; «шанс» показывается из фактической формулы, не подменяется заглушкой.

## Выявленные ошибки E3

- `dev/src/data/gear-recipes.js`: `partFragId` сейчас возвращает `item.id` для **любой** детали; компоненты расходуют одну общую валюту фрагментов.
- `dev/src/ui/overlays/detail.js`: `itemSourceRows(it)` вызывается и для готовой вещи, и для вложенных компонентов.
- `dev/src/logic/gear.js`: `rollItems`/ `grantFrags` дают только фрагменты предметов; готовые предметы не поддерживаются.

## Очередность реализации

1. Data: стабильные ID фрагментов `frag:<itemId>:<part>`; детерминированный, непересекающийся индекс миссий компонентов и единичных источников готовых предметов. Для I–V должен оставаться путь прямого рецепта (либо новый отдельный ключ обычных фрагментов).
2. Logic: отдельный запас целых предметов, корректная сборка с приоритетным расходованием универсальных старых фрагментов, атомарная установка и `Надеть всё`.
3. Rewards: фактические шансы выпадения для миссий, ×1/×5/×10, рейда; источник и UI должны опираться на те же записи, что и награды.
4. Save: миграция новых полей через `fillSave`/`loadSave`, отсутствие потери старых данных.
5. UI: только после утверждения макетов в 844×390 и 667×375. Разделить «Целый предмет» и «Фрагменты компонента», показывать точный шанс и навигацию к соответствующей миссии.
6. Tests: полный охват 156 предметов, 2 непересекающихся множества на каждом составном рецепте, отсутствие целых XI–XIII, правильные вероятности, многократные симуляции, корректная миграция и атомарное списание.
