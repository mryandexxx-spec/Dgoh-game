- Источник утверждённых требований и союзных отрядов: `BH1_RESTORED_APPROVED_SPEC.md`, проверяемые данные: `src/data/baron-legend-approved.js`.

- Не заменять 5 фиксированных пятёрок выбором произвольного отряда.

## Сюжетная модель пяти боёв — предложение

Ниже враги представлены **только как кандидаты для художественного и балансового согласования**. ID взяты из уже существующих персонажей. Противники в сюжетных боях могут появляться в разных стадиях без приписывания этому канонического убийства; сценарий победы не означает гибели именованного персонажа в основной истории.

| Этап | УТВЕРЖДЕННЫЕ союзники (порядок) | ПРЕДЛАГАЕМЫЕ враги | Идея столкновения |
|---|---|---|---|
| I «Тайный союз» | baron, piter, feyd, rabban, margot | thufir, gurney, duncan, leto, paul | Непростой скрытый удар по безопасности Дома Атрейдесов |
| II «Печать императора» | shaddam, fenring, margot, mohiam, legion | leto, thufir, jessica, gurney, duncan | Имперская санкция и политическая ловушка |
| III «Цена предательства» | yue, piter, baron, mohiam, fenring | leto, jessica, thufir, duncan, gurney | Предательство вскрывает оборону дворца |
| IV «Ночь над Арракином» | baron, feyd, rabban, piter, legion | duncan, gurney, thufir, leto, paul | Ночная операция против защитников Арракина |
| V «Триумф Барона» | baron, feyd, rabban, shaddam, fenring | leto, duncan, gurney, thufir, jessica | Заключительная битва за контроль над Арракином |

**Критика собственного предложения:** 5 × 5 именованных героев может повторяться и ощущаться однообразно; для IV стоит рассмотреть 2–3 волны из существующих Атрейдесов/охранников. Однако нельзя добавлять новую армию или менять канон без отдельного утверждения. В финале победа над Лето должна объясняться сюжетно без неканонического «воскрешения» в предыдущих стадиях.

## Рекомендуемая сложность — только вариант для тестирования
- I: одна волна 5×5, обучение синергии Барон/Фейд/Питер.
- II: одна волна 5×5, упор на контроль/поддержку.
- III: одна волна 5×5, защита Юэ как сюжетная задача (дополнительный подвиг, **не обязательный** для разблокировки).
- IV: две волны, сначала оборона, затем командиры (нужны согласованные точные составы обеих волн).
- V: две волны и финальный командир с усилением, без создания нового NPC (нужны согласованные точные составы).
- Статистика противников, уровни, звёзды, ДП и коэффициенты **не утверждены**. Предлагается калибровать не ниже трудности требований 7★/XIII/ДП2–7; точные числа — после локального симулятора.
- В мобильной сцене каждый бой 5 на 5; волны сменяются без дополнительных WebGL Engine и без переинициализации HUD.

## Награды — альтернативы для решения владельца
**A (рекомендовано по аналогии с Муад’Дибом):** 330 осколков суммарно за пять первых побед, достаточных для открытия 7★ легенды (распределение по этапам согласовать отдельно); повторные победы не дают повторных осколков. **Это предложение, не восстановленное решение.**

**B (поэтапный доступ):** первые этапы дают неосколочные награды; V выдаёт все 330 осколков. Плюс — не возникает частичного доступа; минус — первые победы субъективно менее наградные.

**C (гибрид):** осколки за I–IV и достаточное количество за V, плюс символические ресурсы; требует дополнительной экономической оценки, чтобы не превратить событие в ресурсную ферму.

Система должна хранить завершение каждого этапа и награду строго один раз, повторные прохождения — без повторных разовых призов; не менять существующий путь Муад’Диба.

## Архитектура после согласования
1. `data/`: immutable-конфигурация события (предпосылки из `baron-legend-approved.js`, волны, враги, значения, таблица наград); валидация неполного конфига = событие закрыто.
2. `logic/`: чистая проверка всех 10 требований, порядок 5 этапов, фиксированный `squad`, завершение боя и атомарные награды; тестовая фикстура для Марго/Юэ только в тестах.
3. `core/`: добавление прогресса `journeys.baron_legend` только через безопасную идемпотентную миграцию, без изменения существующих roster/prog.
4. `ui/`: использовать общие компоненты легенд/боёв, адаптировать утверждённые 844×390 и 667×375 макеты; без дублирования карточки героя и без новых контролов вне согласованного UI.
5. `render3d/`: переиспользовать текущую Arena, HeroStage, EngineHost и HIGH/MED/LOW; не создавать отдельную игровую сцену на каждую волну.
6. Golden: 200 существующих боёв, meta, saves, DOM PWA+artifact, фиксация союзников, отсутствие обхода блокировки, однократность наград, возобновление после перезапуска, iPhone MED/LOW и 2D fallback.

## Решения, ожидающие согласования
1. Вражеские пятёрки I–V и целесообразность волн на IV–V (предложенные выше — НЕ факт).
2. Диапазон сложности противников и правила дополнительных подвигов.
3. Вариант наград A/B/C и точное распределение по этапам.
4. Поведение при повторном прохождении и снятие блокировки Марго/Юэ только после отдельных будущих событий.
5. Одновременный `baron` и `baron_legend` в отряде — ранее не утверждено, не вводить запрет молча.

**Release gate:** до утверждения решений 1–3 не экспонировать Journey в публичной игре, не сливать Draft PR #24, не публиковать Pages.
