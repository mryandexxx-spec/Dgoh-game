# GFX-01 — Art Bible: Cinematic Dune
24.11.2026 · стандарт для макетов и визуальной разработки по [GFX-2.0](GFX_2_0_ROADMAP.md). База v156 / UI-10, main после PR #296. Числовые значения ниже — стартовые ориентиры прототипа, не утверждённые изменения runtime; конкретные макеты согласуются отдельно.

## 1. Визуальное обещание
Монументальная материальная научная фантастика, в которой герой живёт в пространстве своего мира. Три приоритета в порядке убывания: силуэт и лицо героя; понятное действие и данные развития; атмосфера мира. Не стилизуем интерфейс под веб-сайт, не имитируем дороговизну золотом и свечением. Сохраняем собственный дизайн, не копируем кино или чужие игровые ассеты.

## 3. Композиция и камера
- Один кадр на весь экран, сцена продолжается за информационными группами. Герой занимает ориентировочно 65–85% доступной высоты сцены; лицо, руки и ключевой предмет не обрезать; полный силуэт или осознанный портретный план, не случайная обрезка. Отправная точка кадра — 3/4, спокойная перспектива без широкоугольного искажения; фиксировать FOV/камеру для A/B, выбрать после GFX-02.
- При первом взгляде различимы имя, лицо и мощь; затем звёзды/уровень, доступные улучшения, экипировка; затем детали/описания. Группировка пространством, общей осью и типографикой. Рамка только у интерактивного слота, состояния или выделения. Не вкладывать карточку в карточку.
- Фон ниже героя и текста по локальному контрасту, шуму деталей и яркости. Дальний план без людей/текста/интерфейса; средний план задаёт перспективу; передний — физический пол и контактная тень. Линия горизонта и точки схода согласованы с камерой, стык пола и matte painting не виден. Не ставить героя на универсальный круг/голограмму. Никакого случайного foreground, скрывающего действия.
- Структура и доступ к действиям одинаковы для фракций. Легенда выделяется постановкой и смысловым акцентом, а не дополнительными бордерами; ульта всегда закреплена.
- 844×390 и 667×375 CSS px, landscape, safe areas. Уменьшаем вторичный декор и меняем плотность/внутреннюю прокрутку прежде, чем уменьшать шрифт или кнопку. Общий экран не скроллится.

## 4. UI и типографика
Inter (локальный проектный шрифт, кириллица) — основной; UI kit остаётся источником смысловых токенов, его исторические Forum/Plex не возвращать как новый основной шрифт. Предлагаемая шкала CSS px: имя 22–28/600–700; мощь 20–26/600 с tabular-nums; заголовок группы 13–15/600; действие/основной текст 13–15/500; вторичные данные 11–12/400–500 (не основной длинный текст). При 667 px проверять реальную читаемость, не масштабировать весь экран transform. Не использовать широкую разрядку у кириллицы и капслок в длинных строках. Значения и единицы не обрезать; длинные имена/описания доступны полностью через перенос или детали.
Сетка 4 CSS px, базовые промежутки 8/12/16, большие группы 20–24 при наличии места. Матовые полупрозрачные нейтральные подложки только по необходимости; предпочтительно градиент затемнения по краям, без стеклянных бликов и дорогостоящего backdrop-filter. Пробные нейтрали #101417 / #E9E5DC / #A9B0B4, акцент задаёт мир. Контраст текста ≥4.5:1, крупных заголовков и существенных контуров ≥3:1; проверять на самом светлом и тёмном кадре, не только на плоском цвете. Touch target предпочтительно 44×44 CSS px с непересекающимися hit areas; видимый focus, semantic button, aria-label для иконок, не только цвет. Disabled отличим от активного, причина и стоимость доступны. Сохранять действующие TIER_COL, light/dark, HP/shield, доступность и ДП; фракционная палитра не перекрашивает семантику. Нет новых правил экономики.
Состояния GFX-02: обычный, закрытый (источник осколков/открытие), gear 1–13 и шесть слотов (вставлен/доступен/недоступен), ДП/переход G13, легенда с ультой, длинное имя/значения и быстрый листинг. Роли, фракции, умения, звёзды, уровень, статы, био и все действия доступны. Не скрывать действие ради композиции; при нехватке высоты — внутренний скролл списка, не страницы, закреплённая ульта и действия.

## 6. PBR, свет, геометрия и ассеты
- Камень/ткань — dielectric (metallic 0), металл — физически обоснованный metallic, roughness по состоянию поверхности. Пробные диапазоны roughness: ткань .65–.95, камень .55–.9, металл .25–.65; уточнять по in-game. Нормаль и roughness дают масштаб материала, а не шум поверх цвета. Не запекать блик/контактную тень в albedo героя. Albedo sRGB, normal/ORM linear; проверить каналы и JPEG fallback. Изношенность локальна по краям/стыкам.
- Один мотивированный key, мягкий fill и сдержанный rim при необходимости, совпадающие по направлению и цветовой температуре с matte plate. Не освещать героя равномерно со всех сторон; не терять тёмную одежду на тёмном фоне. Контакт стоп с полом без парения; тень мягкая или жёсткая по источнику. Экспозиция фиксирована для сравнения; не использовать bloom для читаемости лица. Existing HDR/ENV_HDR и material slots прежде новых ресурсов.
- Matte painting только дальний план, настоящий компактный пол и несколько средних планов из геометрии. Статичные пропсы — merge/instance где выгодно, материал переиспользовать с явным ownership. Для пилота не менять rig/mesh героя и боевую камеру; сначала сравнить композицию UI, затем отдельно окружение и свет. 2D fallback сохраняет тему и все действия.
- HIGH — полная разрешённая постановка; MED — цель, baked contact/ambient при выгоде, без обязательного постпроцесса; LOW — тот же силуэт, основные материалы и свет, упрощённые геометрия/тени, статический дальний план. Все решения через quality.js; не увеличивать постоянные проходы без замеров.
- Текстуры по потребности на экране: начать с существующего plate 512², сравнить 1024 только если заметно и укладывается в бюджет; один активный комплект, mipmaps, KTX2 для 3D с JPEG fallback, WebP для 2D. Не путать размер файла и GPU память (512² RGBA8 с mip ≈1.33 MiB, 1024² ≈5.33 MiB). Никаких сетевых runtime зависимостей, второго Engine/canvas/RAF, WebGPU. B3, EngineHost, GameScene, withCtx synchronous, dispose, 0 shader compiles after wake, idle/static.
- Модели: характерный силуэт, узнаваемые лицо/костюм/предмет, корректные пропорции и кисти, material slots, UV, attachment, rig/clip IDs; GLB source → существующий DGM, KTX2. Meshy/Blender кандидаты только после концепта и проверки топологии/весов/лицензии; не выдавать сырой AI mesh за game-ready. Не менять модель в пилоте для изоляции эффекта сцены.

## 7. Иконки и motion
Художественные иконки ресурсов, умений и предметов: один читаемый предмет/действие, единый ракурс и мотивированный свет внутри семейства, чистый силуэт, нейтральный фон/альфа и запас под рамку. Проверять при 24, 32 и 44 CSS px и на реальном фоне; не рисовать цифры, рамку тира, счётчик или подписи в bitmap. Иконки навигации — простые ясные SVG, не пытаться сделать каждую кнопку иллюстрацией. Уже утверждённые солярии, камни су, ДП и способности сохранять до отдельной причины изменения.
Motion — реакция на намерение: нажатие 80–120 ms, смена информационной группы 150–220 ms, смена героя 180–300 ms, редкое событие 350–650 ms как стартовые ориентиры, не задержка ввода. Анимации DOM transform/opacity, без idle layout; смена героя отменяема, последний выбор побеждает, фокус не прыгает; загрузка без устаревшего кадра. Reduced motion — мгновенная смена/короткий fade, LOW без лишних FX. Idle — естественная поза/дыхание, не постоянная тряска, движение камеры или мерцание. Анимация награды только после подтверждения выдачи; никаких изменений RNG, clock, reward commit, save.

## 9. Производство и provenance
Brief → 1 representative concept → согласование → раздельные plate/материалы/геометрия → Blender/Meshy candidate и ручная проверка → оптимизация существующим pipeline → in-game A/B → адресный CI → физическая приёмка. Пример brief: Caladan terrace, low contrast distant ocean, massive wet basalt columns, diffuse overcast side key camera-left, open foreground with perspective for grounded feet, no figure/text/UI/logo, original design. Отдельно фиксировать camera/horizon/light, aspect ratio/crop, используемую модель/ген ID, инструмент/дату/параметры, источник и лицензию, разрешение публикации, source path, output paths, bytes/texture dims, fallback, проверившего и evidence. Исходники dev/assets-src, runtime dev/assets; документация и внешние референсы не входят в build. Не покупать и не запускать платные генерации без разрешения; CC0 (например Poly Haven/ambientCG) проверять на конкретном файле, Mixamo/Fab/Meshy — условия конкретного использования. Не импортировать извлечённые игровые/киношные модели или изображения. AI concept не является доказательством работы или производительности.

## 10. Единая мобильная приёмка (не новые CI jobs)
Матрица: Дункан / молодой Барон × 844×390 / 667×375 × MED/LOW; одинаковый save fixture, состояние, камера/тайминг (кроме проверяемой переменной), качество, warm assets. Дополнительно легенда, закрытый, ДП, крайние значения, быстрые переключения/закрытие, 2D fallback, offline. HIGH desktop если затронут. Снимок baseline v156/актуального main перед реализацией; сохранять SHA, viewport, DPR, gfx, renderer, state, warmup, timings и путь доказательства. Оценивать: фокус/силуэт, свет/стык пола, отсутствие пересечений UI, контраст, полный доступ к действиям; каждый критерий pass/fail/not tested. Не принимать по среднему баллу, если хоть один обязательный сценарий fail.
Метрики: frame time/p95, draws, проходы, RT/GPU memory (оценка отдельно от измерения), cold/warm load, 0 layout в idle, 1 WebGL context, отсутствие роста meshes/textures за 3 цикла (1 warmup + 2 measured), offline и context loss fallback. Сравнить с последней выкаткой; исторические ориентиры ARCHITECTURE §4 для героя MED 120 draws/19 passes/1.8 Mpix/42 MB RT, LOW 75/9/0.4/22 — не новые замеры. Рост >10% любого MED/LOW показателя требует согласования и варианта снижения. SwiftShader не доказывает iPhone GPU или нагрев; реальный Safari/PWA отмечать отдельно. Не обновлять golden без согласования. GFX-01 docs-only → strict + selection + final gate; GFX-02 runtime — короткий smoke + затронутые UI/3D/PWA по текущему diff.
