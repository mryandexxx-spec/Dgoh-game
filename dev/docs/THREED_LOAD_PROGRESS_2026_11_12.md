# 3D — индикатор сетевой загрузки в диагностике (12.11.2026)

## Назначение

Показывать в существующем оверлее **?perf / пять касаний версии** фактическую загрузку сетевых 3D-ассетов, вместо ошибочной фразы «3D не запущено» до старта EngineHost. Не блокировать лагерь/боевые экраны дополнительным ожиданием.

## Состояния

- `3D ожидает запуска` — Babylon ещё не запрошен (ленивая загрузка).
- `3D загружается` — запрос Babylon выполняется, ассеты грузятся параллельно.
- `3D готово` — Babylon и readiness доступны; отдельные необязательные модели всё ещё могут догружаться.
- `WebGL недоступен` — у устройства нет контекста WebGL; 2D fallback остаётся.
- `3D: ошибка загрузки движка · можно повторить` — ошибка/тайм-аут скрипта Babylon; будущий вызов loadB3 может повторить.

Счётчик `3D-ассеты`: скачано / размер (МБ, два знака), процент **только при известных объёмах текущих сетевых запросов**. Если Content-Length отсутствует — «размер уточняется» и без выдуманного процента. После завершения подсчёт уточняется по реальным полученным байтам. Число активных запросов и ошибок видно в полной панели; краткая панель показывает текущий статус и МБ.

## Архитектура и ограничения

- `dev/src/assets/models.js` — `trackedFetch` учитывает модели DGM, mocap JSON, предварительно загружаемые KTX2 и их зависимости, env-текст в формате артефакта. Учёт без второго fetch/дублирования байтов.
- `dev/src/render3d/base.js` — `b3LoadStatus()` различает idle/loading/ready/failed/unavailable; существующие 7-секундный asset readiness timeout, 12-секундный script timeout и 2D fallback не менялись.
- `dev/src/ui/perf-overlay.js` — счётчик обновляется имеющимся таймером оверлея 500 мс, **без нового rAF/постоянных DOM-запросов в игре**, сохраняется мини-режим.
- Числа относятся **только к потокам, проходящим через загрузчик assets/models.js**, а не к абсолютно всем 3D-файлам: ленивый `babylon3d.js`, JPEG-фолбэки и .env, самостоятельно запрашиваемые Babylon, не включены. Не писать «общий размер 3D игры»; для полного объёма нужен единый учёт загрузок Babylon/чанка.
- `Content-Length` — ожидаемый размер ответа; при стриминге в браузере количество байтов может относиться к распакованному телу. По завершении для каждого ответа используем измеренную длину тела. Нет запроса размеров из сети заранее, чтобы не создавать трафик.

## Проверки

1. iPhone Safari landscape 844×390 и 667×375, ?perf и пять касаний версии: до начала B3 не показывать «не работает», при загрузке — статус и рост МБ, после — «3D готово».
2. Плохая/задержанная сеть: данные увеличиваются монотонно; при неизвестном Content-Length не выводить ложный %; fallback сохраняется, замороженный необязательный Муад’Диб не блокирует сцены.
3. Offline/ошибка чанка: статус ошибки отличается от WebGL-недоступности; переход к 2D и повторная попытка работают.
4. Мини-режим/полный режим и сохранение показа performance overlay.
5. CI: check-deps, build, check-bundle, Golden, DOM 844/667, WebGL lifecycle. Не менять графические профили/модели/экономику.
