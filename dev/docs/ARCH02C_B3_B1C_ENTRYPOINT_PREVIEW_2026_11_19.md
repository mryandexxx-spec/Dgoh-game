## This A0 slice is NOT the final B1c production switch

The shipped v140 and default local source boot both still use the legacy synchronous `start(data)` path and legacy unguarded `persist0()`. Existing golden/ESM initial order depends on that historical path. Activating B3 gate as default today would affect 200 battle goldens, 41 screens, SW/offline, hot reload and B2 import/recovery, without an approved safe migration/cutover. Therefore **B1c-A0** adds a deliberately inert-by-default preview dispatch inside existing `dev/src/core/boot.js`, with **byte-identical** `dev/src/boot.js`:

- The existing `start(data)` is the real application startup callback, passed unchanged by frozen `dev/src/boot.js` to `window.claude.hot.ready` or invoked on normal page load. The original `dev/src/boot.js` must pass the historical ARCH-01C4c Git-blob fingerprint gate without weakening the test.
- If and ONLY if the test/preboot environment has explicitly set `window.__DGOH_B3_B1C_BOOT_MODE__ === 'writer-preview'`, it calls existing `start.writer(data)` (B1b) which arms the input/lifecycle gate, acquires native Web Locks BEFORE loading `S`, and passes all persistence through verified B1 checkpoints. A denied lock never falls back to the legacy boot.
- In all other modes the existing `start(data)` executes historical `set_S(initialSave(data))` and subsequent logic exactly; default production v140-compatible behavior remains unchanged.
- Preserves `start.writer` and `start.writerLifecycle` references to allow native Chromium acceptance to use the *same existing callback* as the application host. The writer's internal synchronous `start(data)` call uses a temporary scoped reentry guard (with `finally`) only AFTER it has acquired the lock; a failed preview remains one-way blocked even if its opt-in flag is removed, so the previous legacy boot cannot be reopened. No new named ESM exports, data schema, storage key, service worker, version number, economy, battle or asset changes.
- This preview flag is **not an owner-facing runtime feature or safe production toggle**; no user should enable it in DevTools on v140. It enables deterministic and native proof of the actual composition-root call path before the separate production cutover decision.
