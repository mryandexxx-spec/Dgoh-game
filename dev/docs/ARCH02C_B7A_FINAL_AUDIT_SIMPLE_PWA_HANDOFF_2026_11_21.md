## Owner-approved streamlined path (no additional B7b/B7c implementation gates)

1. **Before release, on the old v140 installation:** finish/exit active battles; use **Профиль → Экспорт сохранения**. Copy the full code into **Notes or a file outside the PWA**, ideally with a second independent copy. Reopen that destination and confirm the long code really exists there (not just on the clipboard). If export errors or warns the saved snapshot excludes current RAM progress, **STOP** until verified.
2. **Release is still a separate explicit owner action.** Create a minimal v141 release PR (version bump + root build, unchanged `dune-goh-v1`), run full exact-head CI, merge and verify public Pages and effective SW version. A green development PR alone does not publish a new app.
3. Close all old v140 Safari/PWA tabs or icons before new-version startup. Only **after** the externally stored code has been verified and the released v141 is accessible: remove/reinstall the PWA if desired. Open online once, verify **v141** in the app before restoring.
4. If the new installation already shows the correct existing progress, **do not import an older snapshot unnecessarily**. Otherwise use **Профиль → Импорт сохранения → Проверить код → Подтверждаю замену**, then reload the PWA as instructed. Compare unlocked heroes, account level and a couple of resource balances; relaunch once and verify persistence.
5. Keep the external backup after successful import. If Web Locks are unavailable, the code is rejected, old v140 opens, or imported progress differs, **do not clear data repeatedly**; stop and investigate while the external copy remains intact.
