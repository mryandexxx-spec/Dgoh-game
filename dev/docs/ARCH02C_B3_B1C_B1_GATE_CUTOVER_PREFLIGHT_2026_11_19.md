## Decision: staged B1, mandatory production switch is BLOCKED on B3-B2

Turning the default `start()` branch from legacy to writer-preview **before B3-B2** is unsafe, even if the exclusive lock and two-page Chromium opt-in path are already proven. Existing public `loadSave.checkpoint.commit/recover` and `ui/wiring.js` B2 import confirmation are independent write operations; blindly switching startup would leave a lock-bypassing direct import/recovery path in the same game. A cached v140/older PWA is an uncooperative writer that ignores Web Locks. The live legacy game and golden baseline must not be silently changed while an approved user transfer/release and real Safari validation are pending.

**Thus this B1 PR is intentionally PRE-CUTOVER and NOT a production-enablement patch.** Normal `start()` still uses legacy mode. Explicit development/CI `writer-preview` still exercises real composition-root lock acquisition and verified checkpoint. An independent B3-B2 PR must provide lease-aware protected import + recovery, including empty-store import after a fresh install, conflict semantics, rollback/unknown-commit handling and blocked-tab UI. Only then should a *separately reviewed* final default-boot switch be proposed, followed by exact-head full CI, actual PWA offline/Chromium and physical iPhone Safari testing, and owner release approval.

## B1 fail-closed safeguards implemented now

1. `core/save.js`: the public B1/B2 `loadSave.checkpoint.commit/recover` APIs reject `writer-required` without reading or writing progress once a writer gate has been armed. The private `commitCheckpoint` used by `loadSave.writer.commit` remains under the existing checked live lease, so normal gated `persist/persist0` continues to work. Ungated legacy B2 test API is unchanged (no unannounced behavioral change to published v140). B3-B2 must explicitly replace those public paths with an authorized writer-owned transaction; it must NOT simply remove these checks.
2. `core/boot.js`: arm the one-way gate and capture-phase input blocker *before* refusing hot-reload injected `data.save` or a late gate. Removing the preview flag after a rejection must never re-enter writable legacy `start()` in the same JS heap. Native lock absence, busy lock, pagehide, freeze, BFCache, unsupported or stale session still refuse entry and cannot reacquire stale RAM.
3. `core/boot.js` / `ui/wiring.js`: a denied/busy/unsupported tab must not read even the verified primary save merely to build its blocked-screen UI. Verified rescue code is available only when this heap had previously obtained the native exclusive writer lease; the export always uses inspected primary bytes, never unacknowledged RAM. This is an access restriction, not a promise of cross-version safety. Previously owned pagehide rescue still works.
4. Keep frozen `dev/src/boot.js` byte-identical and `set_S(initialSave(data))` the first AST statement in `core/boot.js start()`. No changes to named ESM exports, v1 save key, SW, PWA root, golden saves, 3D, economy, version or architectural CI gates.
