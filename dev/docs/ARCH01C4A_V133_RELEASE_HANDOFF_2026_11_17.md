2. Squash merge с **точным subject `release(arch): publish v133`**. Одноразовый guard сработает только от push этого релизного коммита в `main` и точного subject, проверит `dev/version.json={"v":133}`, старый опубликованный SW `2c8aab985b`, три оставшиеся запрещённые зависимости, исходную форму `data/boss.js`, порядок import в `logic/battle/stats.js`, существование B1-тестов и сохранность C3b0/C2d/looks NO-GO, Conquest NOTES/refill API и подписанные экспортные имена. Только затем один раз dispatch `validate-pwa.yml` с `publish=true` на `main`.
3. Официальный publish-run должен собрать этот SHA один раз, валидировать 19/19 required jobs, SHA-256 manifest, version+SW hash и только затем **Publish verified PWA to GitHub Pages SUCCESS**. Не утверждать успех, если gate/Pages failed, skipped или pending.
4. Получить **независимый** root Pages workflow SUCCESS, точно на новом root-коммите от официального publish, подтвердить, что родитель root — release source, поменялись только `app.js/sw.js`, `dev/version.json={"v":133}`, SW изменился относительно v132. Записать actual root SHA, SW, число/хеш manifest, оба run IDs в [Issue #132](https://github.com/mryandexxx-spec/Dgoh-game/issues/132).
5. После подтверждённой публикации — **отдельный docs-only PR**: записать receipt сюда и в `CHANGES_STATUS.md`, удалить одноразовый guard; полный CI, **без второй публикации**.
