# ARCH-01C2b — изоляция проверки открытия миссии от core/state

**Дата:** 16 ноября 2026. **База:** актуальный main `ed734a4bfb3e1048fb8c4cc558d1ec3b1924a487`, опубликована **v127**; [Issue #132](https://github.com/mryandexxx-spec/Dgoh-game/issues/132), [ARCH-01C2a PR #139 MERGED](https://github.com/mryandexxx-spec/Dgoh-game/pull/139).

## Один кандидат: baseline 13 → 12

Единственный оставшийся импорт состояния в `data/campaigns.js`:
`import { S } from '../core/state.js';`. Он используется **только при вызове** `nodeOpen(i)`:
`const n=NODES[i], prev=i-1; return (prev<0 || NODES[prev].camp !== n.camp) ? true : !!S.cleared[prev]`.

**Решение:** оставить исходный `nodeOpen` (старый named export) как узкую совместимую callable-функцию без импорта состояния из `data`; добавить строго однократную `bindNodeOpenRuntime(rule)`. Чистая `data/campaigns.js` продолжит объявлять `CAMP_DEF`, `NODES`, `NODE_SCENES`, `nodeTitle`, `nodeEn`, `nodeCost` без изменений. Новый `logic/campaign-gates.js` владеет *бит-в-бит* старым правилом на live `S.cleared`; `core/boot.js` регистрирует этот обработчик до первого `start()/render()` через импорт, не читая `S` при evaluation.

**Критически важно:** старый `nodeOpen` импортируют `ui/views/camp.js`, `ui/views/campaign20.js`, `ui/events.js`, `ui/battle/battle-ui.js`. Ни один UI/лагерь/3D файл **не меняется**; новая логика подключается в имеющемся разрешённом `core/boot.js`, как предыдущий C1b `logic/journey-gates.js`. Missing binding обязан явно бросить ошибку, а не автоматически открыть миссию.

## До реализации — обязательный virtual esbuild

Первая версия Draft PR содержит **только** `dev/tests/ci/arch01c2b-virtual-order.mjs`, подключение в существующем AST gate и этот документ. Виртуальная сборка из текущего `src/main.js` (production esbuild `format:esm`, `treeShaking:false`) меняет `data/campaigns.js` и `core/boot.js` **только в оперативной памяти**; `logic/campaign-gates.js` задаётся виртуально. **Никаких** настоящих исходников, SPLIT, baseline, golden, версии или опубликованной PWA на диагностическом шаге не меняется. Сравниваются точные позиции всех **164** текущих модулей. Сдвиг старых модулей — STOP/перепроектирование, не изменение SPLIT ради прохождения.

## После успешной виртуальной проверки — implementation acceptance

1. Один новый `logic/campaign-gates.js`, плюс минимальные правки `data/campaigns.js`, `core/boot.js`. Baseline **13→12**, 0 новых/устаревших импортов, `logic → ui` 0.
2. Сохранить прежнюю наблюдаемую семантику `nodeOpen`: 210/210 значений для пустого, частично и полностью пройденного сейва; первая миссия стороны (индексы 0, 70, 140) открыта независимо от прошлого, остальные требуют `!!S.cleared[i-1]`. Проверить разные значения звёзд, обновление сохранения после загрузки, первую главу, границы глав, переход «Следующая миссия». Текущий код **не** ставит дополнительные проверки номера миссии или её уровня, не вводить их. Проверка должна работать на **PWA и artifact**.
3. Проверить, что `S` не читается до `start()`; вход через глобальную `nodeOpen` после связки ведёт себя как исходная реализация, а отсутствие регистрации никогда не превращается в `true`. Идентичность live `S.cleared` при новых сохранениях и миграциях.
4. Старые 164 ESM-маркера сохраняют относительный порядок; добавить только один обоснованный marker в `SPLIT`, не изменять старые. `check-bundle OK (165)` и экспортный API без пропавших имён; AST gate, check-deps, SCC/TDZ и тесты 210 миссий.
5. Полный mandatory CI: golden 200 боёв, мета, сохранения, 41 экран **PWA и artifact**, E3 iPhone DOM, offline/SW, WebGL на телефоне MED/LOW и desktop, строгий 3D lifecycle. Эталоны не обновлять.
6. **Ни при каких обстоятельствах не менять лагерь:** `ui/views/lobby.js`, зоны/кнопки/стили, 3D-сцену и навигацию. Не менять Campaign 2.0, 21 3D-карту, 210 `NODES`, цены 6/8, экономику, RNG, награды, баланс, прогрессию, арт, формат сохранений.
7. Новая реализация только в Draft PR; **нет разрешения на merge, повышение версии или публикацию**. Физическая проверка v127 на Safari/iPhone пока не подтверждена.
