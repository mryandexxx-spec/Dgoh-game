## Резервная копия и iPhone Safari: отдельный пользовательский барьер

**Одна лишь команда на релиз не подтверждает существование полной внешней копии или реальные испытания Safari.** Проверка файлов пользователя недоступна через GitHub. Для безопасного обновления пользователю нужно **до открытия/удаления новой PWA** выйти из боя, выбрать **Профиль → Экспорт сохранения**, сохранить полное проверенное сохранение в «Файлы»/заметки за пределами PWA и повторно открыть файл. Желательна дополнительная независимая копия. Буфер обмена и резервная копия на том же origin недостаточны.

Обновление на существующем origin **обычно сохраняет локальные данные**, но гарантий против очистки site data/iOS quota нет. **Не удалять установленную PWA и не очищать её данные.** В новой версии при сохранённом прогрессе не импортировать старый файл. В случае необходимости импортировать только заведомо полный/проверенный файл и подтвердить замену, затем cold restart, сверить героев, валюты, историю Conquest и дневные лимиты. Если Web Locks, импорт или хранилище заблокированы — **STOP**, не пытаться циклически переустанавливать.

Физический iPhone Safari/WebKit, установка, фон/BFCache, offline, файловый picker, нехватка места, реальное подтверждение внешнего файла **не покрыты Chrome CI и не заявляются пройденными**. Отдельная ручная пользовательская проверка должна быть отмечена фактом после релиза. Новая PWA — не основание для команды «можно переустанавливать» без проверенного бэкапа.
