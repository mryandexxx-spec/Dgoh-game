# Аудит производительности и памяти — Dune: Galaxy of Houses (PWA)

> Историческая справка: аудит монолита до рефакторинга (фазы 0–7, v45–v68). Номера строк — по старому `index.html`. Актуальные бюджеты и правила — `dev/ARCHITECTURE.md` §4.

**Объект:** `dune-pwa-flat.zip` → `index.html` (7 113 строк, 5,04 МБ) + `babylon.min.js` (Babylon.js **9.30.0**, полный UMD, 8,57 МБ) + `sw.js`.
**Режим:** только чтение, код не менялся. Номера строк — по `index.html` из архива.
**Контекст:** в коде уже есть детектор крэшей iOS (стр. 4001–4008: «Бой прервался из-за нехватки памяти») и фоллбек на 2D при `webglcontextlost` (стр. 5487). Это симптомы, причины ниже.

Обозначения: 🔴 критично · 🟠 высоко · 🟡 средне · ⚪ низко. Оценки объёма памяти — расчётные (формулы указаны), не замеры на устройстве.

## 2. Реестр утечек памяти

### Цикл «бой → результаты → лагерь → новый бой» на телефоне — что реально происходит

| Шаг | Действие | Новые объекты | Что остаётся |
|---|---|---|---|
| 1. Старт боя | `launch` → `freeStages()` (6010) → `new Arena3D` (5485) | Engine №1 + Scene + пост-обработка + герои | контексты лагеря/героя — «зомби» до GC |
| 2. Результаты | `finish()` (5746) добавляет модалку | — | **арена продолжает рендер 60 fps** с полным пост-процессом |
| 3. В лагерь | `leaveBattle` → `arena.dispose()` → `render()` → `mountCampStage` (3923) | **Engine №2** + полная пересборка сцены лагеря + 5 PBR-героев + повторный декод текстур Дункана | контекст №1 — зомби |
| 4. Новый бой | `openSquadSel` → `launch` → `freeStages` | **Engine №3** | контекст №2 — зомби |

**Итог: каждый цикл = 2 новых WebGL-контекста и 2 незакрытых.** Открытие окна героя — ещё +1.

### 3.2 Лагерь (`CampStage`, 3857–3916) — **главный источник нагрева в меню**

Работает на 60 fps всё время, пока открыт лагерь (самый частый экран):
- **Два генератора теней:** солнце из `buildEnv` (1024/2048 PCF) **и** `PointLight` костра (3872) — **кубическая карта = 6 проходов теней каждый кадр** по всем кастерам (5 героев, палатки, камни, брёвна; 3897 добавляет все меши героев).
- SSAO2 radius .9, DoF, GlowLayer, HDR-конвейер, bloom, анимированное зерно (3889).
- Частицы: пламя 400 (`emitRate 260`), искры, дым, пыль, 900 звёзд (ночь `sietch`).
- 5 PBR-героев с translucency/sheen, до 8 источников света.

## 5. План исправлений (каждый шаг независим и проверяем)

Порядок — по соотношению эффект/риск. Игровая логика (1388–2040, мета 4367+) не затрагивается ни одним шагом.

**Шаг 0. Инструментирование (база для всех проверок).**
Debug-оверлей по `?debug=1`: FPS, `SceneInstrumentation.drawCallsCounter`, `scene.meshes/materials/textures.length`, число живых `Engine`, `engine.getLoadedTexturesCache().length`. Скрипт «20 циклов бой→лагерь» для десктоп-Chromium (Playwright) + ручной прогон на iPhone с Safari Web Inspector (Timelines: JS Allocations, Layout & Rendering, Media/Canvas).
*Проверка:* базовые цифры записаны в таблицу до правок.

**Шаг 1. Освобождать контекст.** Во всех `new B3.Engine` (3182, 3743, 3945) — `loseContextOnDispose: true`; после `dispose()` — `canvas.width = canvas.height = 0` и удаление канваса из DOM.
*Проверка:* Web Inspector → вкладка Canvas: после 20 циклов живых контекстов ≤ 2; перезагрузок нет.

**Шаг 2. Кэшировать лагерь между боями** (вместо пересоздания): при старте боя `CampStage` не уничтожать, а «усыплять» — `stopRenderLoop` + `pipe.dispose()` + `ssao.dispose()` + `glow.dispose()` (освободить RT, сохранив геометрию и текстуры); при возвращении восстанавливать пост-обработку. Работает в паре с шагом 1; на LOW-профиле допустимо оставить полное уничтожение.
*Проверка:* возврат в лагерь без `new B3.Engine` (счётчик из шага 0), время возврата < 300 мс.

**Шаг 3. Пауза рендера на экране результатов и в простое.** В `finish()` — отрисовать финальный кадр и остановить цикл арены (или 10 fps). Ограничитель FPS: 30 fps, когда `BT.waiting`/диалог/попап, 60 — во время анимаций действий.
*Проверка:* Timeline на экране результатов — ~0 кадров/с; в ожидании ввода — 30.

**Шаг 4. Профили графики LOW/MED/HIGH.** Телефон по умолчанию = MED: без SSAO2 и DoF (DoF только в синематиках ульты), один из Glow/Bloom, `hdr=false`, без MSAA при FXAA, статичное зерно, DPR ≤ 1,5. `SAVE_LOW` расширить до полноценного LOW.
*Проверка:* скриншоты A/B в 3 сценах; время кадра GPU и VRAM (оценка по RT) ниже.

**Шаг 5. Тени.** Статичным пропсам — `cast = false` (или запечь тень в вершинные цвета земли); `shadowMap.refreshRate = 2`; в лагере убрать кубическую тень костра (оставить солнечную или блоб-тени под героями); в `HeroStage` PCSS → PCF `QUALITY_MEDIUM`.
*Проверка:* число проходов теней на кадр (Spector.js на десктопе) — 1 вместо 7 в лагере.

**Шаг 6. Свет.** `maxSimultaneousLights = 4`; `glLight.setEnabled(intensity > 0)`; свет легендарных героев → emissive + glow; 4 огня пещеры → emissive-сферы + вершинный цвет.
*Проверка:* в Spector число циклов света в шейдере ≤ 4; визуал A/B.

**Шаг 7. Текстуры Дункана.** На телефоне грузить 512² (уменьшать при загрузке через канвас или заранее подготовленной копией); кэш `Texture` на движок (одна загрузка на сцену, а не на экземпляр); `skeleton.dispose()` при смене героя (L6).
*Проверка:* сумма `getSize()` текстур сцены — минус ~45 МБ на экземпляр.

**Шаг 8. Убрать аллокации из циклов.** Константы цветов (`const C_TGT = col3('#d9604f')` и т.д.) и `copyFrom` вместо присваивания новых объектов; временные `Vector3`/`Viewport` на модуль; `LerpToRef` вместо `Lerp`; очередь `fxq` — отсортированный массив с курсором; `tr/summons` — удаление на месте.
*Проверка:* Safari JS Allocations в простое боя — плоская линия.

**Шаг 9. HUD без forced layout.** Кэш `uid → element` при `renderBattle`; `gBCR` поля/канваса только при ресайзе; позиционирование через `transform: translate3d()`; `--fh/--w` писать только при изменении > 1 px. То же для `CampStage.post`.
*Проверка:* Timeline «Layout» — 0 событий на кадр в простое.

**Шаг 10. Частицы.** На телефоне ×0,4 к количеству (шторм 2600 → ~1000, дождь 1600 → ~650), `GPUParticleSystem` на WebGL2; `preWarmCycles` ≤ 40.
*Проверка:* время скрипта на кадр в сцене `storm`.

**Шаг 11. Прогрев шейдеров и пул FX.** При создании арены — однократно создать все варианты FX-материалов и вызвать `forceCompilation`; дым создавать сразу; FX-меши (кольцо, тор, трубка, сфера) брать из пула вместо create/dispose.
*Проверка:* нет кадров > 50 мс при первом применении каждого умения.

**Шаг 12. Слияние пропсов и общие материалы.** Кэш материалов по ключу в `mat3/basic3` для пропсов; `Mesh.MergeMeshes` / thin instances для города, башен и окон; `freezeWorldMatrix()` и `material.freeze()` у статики; земля — 96–120 подразбиений.
*Проверка:* `drawCallsCounter` в сценах `giedi` и `arrakeen` — минус 150+.

**Шаг 13. `errLog` с троттлингом.** Повтор той же ошибки — только счётчик в памяти, запись в `localStorage` не чаще раза в 5 с, `console.warn` — первые 3 раза.
*Проверка:* искусственный `throw` в цикле — 1 запись за 5 с.

**Шаг 14. CSS.** Пульсации `box-shadow` → анимация `opacity` у псевдоэлемента с заранее отрисованной тенью; `filter: brightness` → `opacity` наложения; `--ga` у легендарных карточек — только для видимых (IntersectionObserver) или статично.
*Проверка:* Timeline «Paint» в ростере/бою.

**Шаг 15. Таймеры и запекатель.** Опрос 400 мс → явный `resume` в `closeOverlay/closeInfo`; `renderRes` — обновлять только изменившиеся текстовые узлы; запекатель запускать только когда нет других 3D-сцен (или на том же движке — см. план рефакторинга).
*Проверка:* в простое меню — 0 вызовов `innerHTML` в секунду.

**Шаг 16 (опционально, отдельно от перфа).** Исправить ключ анимации (3276): счётчик действий вместо `B.log.length`.
