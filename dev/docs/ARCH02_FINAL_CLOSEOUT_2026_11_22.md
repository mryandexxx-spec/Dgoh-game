### Сознательно принятые ограничения (не новые этапы ARCH-02)

1. **Полностью офлайн-часы — не античит.** Без доверенного сервера/внешних подписанных фактов нельзя отличить честную длительную паузу от подмены `Date.now()` **перед** запуском. Вернуть честно накопленные Воду, Свечи, Решимость и выносливость с исходными капами важнее спекулятивного ограничения времени. Новая выдуманная дата всё ещё может открыть новые календарные права; возврат к уже использованным датам Trials/магазинов защищён историей. Никакого молчаливого обнуления.
2. **Локальные данные не являются серверной резервной копией.** Удаление всего site data, evict origin, потеря телефона или недоступный Web Locks API могут оставить прогресс недоступным. Существующий checked backup на том же origin не переживает его удаление; экспортировать полный проверенный `dune-goh-v1` за пределы PWA и перепроверять реальный файл.
3. **Конечная квота `localStorage`.** Архив недель и дневных лимитов может расти. Нет автоматической очистки, скрытой миграции или доказанного способа обойти лимиты Safari. Quota/uncertain error должен оставлять подтверждённый предшествующий primary и блокировать сомнительный commit. Для больших сейвов предусмотрен файл, но импорт ограничен 8 МБ и квота записи может отказать.
4. **Отдельные P2 продуктовые вопросы:** визуальные настройки/предпочтения могут оптимистично обновиться в RAM до отказавшего `persist()`; boot migration может показать toast до сохранения; прерванный оплаченный бой может не вернуть стоимость без успешного завершения. Автоматическую компенсацию/повторную выдачу без продуктового решения запрещаем, чтобы не дублировать награды.
5. **Версионная и пользовательская граница:** старая закешированная v140 не подчиняется новой Web Locks дисциплине; пользователь может вручную импортировать старый v1 и осознанно откатить прогресс. Не запускать старый клиент вместе с новым; импортировать только после проверки выбранного снимка. Старые исследовательские PR #194/#200 и иные исторические Draft-ветки не представляют незавершённую обязательную реализацию.

Указанные P2/архитектурные границы — **отдельный техдолг / принимаемые условия**, не причина открывать ARCH-02D-B4b3/B5 и не повод бесконечного аудита. Новый ARCH-пакет возможен только для **воспроизводимого P0/P1**, с путём кода, шагами, измерением угрозы проверенному прогрессу, минимальным исправлением и CI-критерием. Сначала исправлять в новом продуктово мотивированном PR, а не делать абстрактный рефакторинг.

## Физический iPhone Safari / release acceptance — НЕ ВЫПОЛНЕНО CI

Это **отдельный допуск выпуска**, не недоказанная «зелёная галочка» архитектуры. Нужна проверка владельцем на реальном iPhone (Safari/PWA landscape), а не утверждение о выполненном тесте:

1. **До любых изменений установленной PWA**: выйти из боя, открыть **Профиль → Экспорт сохранения**, выгрузить **проверенный полный JSON** (или полную текстовую копию старой версии) во внешнее приложение «Файлы»/другое хранилище, открыть файл заново и убедиться, что он полный; желательно две независимые копии. Только буфер обмена — не бэкап. При неопределённом commit/непроверенном RAM — STOP.
2. Не удаляя оригинальную установку, проверить на безопасной тестовой копии/другом origin либо резервном устройстве: импорт через нативный выбор файла, предварительная проверка, явное подтверждение, обязательный reload и cold restart; сравнить персонажей, уровень, ресурсы, истории Conquest и использованные дневные лимиты. **Не импортировать тестовый сейв поверх настоящего игрового.**
3. Проверить запуск и продолжение **офлайн**, сворачивание/возврат, блокировку второй вкладки Web Locks и отсутствие дубля награды; при переходах даты/часового пояса использовать только тестовые данные/устройство. Никаких live манипуляций временем и удаления localStorage для проверки.
4. При ошибках quota/security/недоступных Web Locks/сомнительной восстановленной истории — **STOP**, сохранить внешнюю копию, не перезапускать импорт циклом. Проверить отдельно поведение нехватки места без риска для основного сохранения.
5. Новый релиз — только по отдельной команде владельца, после release Fast/Full/strict/Golden/WebGL/offline, проверки **фактически опубликованных** `dev/version.json`, root app/SW и Pages, затем проверки установленной PWA. **Не говорить «можно переустанавливать» до существования проверенного внешнего полного бэкапа и подтверждённой публикации.**
