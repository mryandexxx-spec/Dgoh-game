2. Define a shared material language: matte patinated bronze, restrained sandstone accents, charcoal/brown substrate, light from a consistent direction; hierarchy via value, relief, spacing, not excessive gold bevels or glow. Start with a contact sheet of component families, NOT a generated screen. Each family has named visual roles and measured minimum/maximum bounds. Use existing licensed art or separate native ImageGen assets with alpha, no text/UI mockup in asset, preserve originals and source hashes; reject failed generations rather than silently crop composite screens. No need to regenerate already suitable art.
3. Produce five families: trade card (normal/selected/sold/insufficient), primary/secondary action (normal/pressed/disabled/focus), nav tab (normal/selected/pressed/focus), resource bar (normal/compact/large balance), availability indicator (available/low/sold). Keep visible labels and keyboard focus; avoid conveying state solely by color. Replace technical fraction with readable stock semantics without changing numbers. Footer must belong to navigation/catalog hierarchy. Review long Russian strings, large prices, disabled state. Touch targets and safe-area fit measured; no screen scroll; internal catalog scroll allowed. No hover-only behavior.
4. Implement reusable skin geometry as real 9-slice corner/edge/center assets with fixed margins, no corner deformation, seams or stretched ornament. Use SVG explicit cropped fragments already proven in the master; CSS border-image later when runtime approved. Separate live text/icons from surfaces. Maintain semantic tokens (material, foreground, border, spacing, type, state) and component recipe + state matrix; existing typography tokens remain baseline. DTCG 2025.10 is a reference format, no forced migration or dependency.
5. Assemble one bounded candidate in existing SVG generator; retain original art bytes and fixture bytes; compare named layers and pixel masks outside intended component changes. Render all 14 states at both native sizes (seven states per size) and two Inkscape exports. Check text overlap, clipping, currency provenance, asset alpha/size, exact cancel-return static frame, scale margins, and consistent render fonts; document any unexpected pixel differences. Static design tests do not establish transactional behavior, device acceptance or accessibility compliance.
6. Strict artistic review separately from technical checks: composition, unity, material quality, hierarchy, readability, state recognizability, distinct Dune character. Reject generic web styling, noisy frames, repetitive heavy gradients, fake neon, all-gold surfaces. Include old/new full-size and component-level comparisons; score and identify real limitations. One coherent pass plus bounded defect corrections; if gate fails, state blocker and stop, no infinite cosmetic polish. Save canonical archive in Library, source hashes and receipt in docs-only PR. Merge only green required CI. Ask owner to approve design before functional integration. Do not modify game runtime, economy, saves, Pages or change other screens during this stage.
